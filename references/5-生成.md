# 5 生成與驗片（第 4 站）

## 1. 每一批生成前

1. 生成授權卡已核准：哪幾鏡、模式、檔位、條數、seed、預估時間。卡上沒列的不生成。
2. 使用者要看進度的話，在瀏覽器開一個 ComfyUI 分頁（設定的 `comfy_url`）；Windows＋Chrome 可以用 `comfy.open_chrome_once()`，開過就不再重開。
3. 每支提示詞 lint 過（❌ 不送）；每張節點圖 `comfy.check_graph` 過（佇列送件時會自動檢查）。
4. 換模型家族前清顯存（`comfy.free()`，佇列空的時候）。順序：Qwen → H3 → ACE-Step。
5. 送件走佇列帳本 `_腳本\佇列.py`：`佇列.add(編號, 節點圖, [專案裡的輸出路徑], meta=…)` 一次排好，再在背景跑 `python _腳本/佇列.py wait`。H3 影片只能經佇列送，`comfy.run` 不送 H3 影片。meta 要有「鏡」「提示詞」「seed」，還有這一條實際掛的檔：`refs`（參考圖、音色檔的專案相對路徑，照掛的順序）、`first_frame`（首幀路徑，接力的鏡寫 `接力`）。佇列送出前只查一條：**掛的每一個檔都在 `已核可/` 裡**（存在、路徑在 `已核可/` 底下、數量等於節點圖裡的圖和聲音節點數）；不在就擋下，不送。
6. 接力（下一條的首幀＝上一條的某一格）：`佇列.add(…, after=(前一條, -1, LoadImage 節點))`。前一條完成後先跑 `cut`，疑似片中切鏡或漏出參考圖就停在「等你看」，不會把壞掉的結尾接下去；看過沒問題 `release`。
7. 每次送件把實際送出的提示詞、參考圖檔名順序、seed、尺寸、步數寫進 `生成紀錄.jsonl`（佇列和 `comfy.run` 自動記）。任何清單、縮圖表都從這個檔反查產生；沒紀錄的不能進 `已核可/`。

## 2. 本機環境

| 用途 | 模型 | 節點圖（`_腳本\comfy.py`） |
|---|---|---|
| 角色板、場景卡、道具卡 | Qwen-Image 2.1（文字生圖，cfg 1：負面欄不起作用） | `qwen_t2i` |
| 分鏡圖（＝首幀）、改圖 | Qwen-Image 2.1 編輯模式，`<image1>` 是畫布（最多 10 張） | `qwen_edit`（`size=(768,1344)`） |
| 片段 | H3 ref2va 權重、`MiniMaxH3ReferenceToVideo`；首幀接第一張參考圖並用 `guide0=True` 釘在第 0 幀，尾幀用 `end_frame` | `h3_ref`（`**PROFILES[檔位]`） |
| 音色檔 | H3 fl2va，416×736，只解音訊 | `h3_voice` |
| 旁白、心聲 | H3 參考模式，416×736，只解音訊，掛音色檔 | `h3_vo` |
| 配樂 | ACE-Step 1.5 turbo | `ace` |
| 剪接、混音 | ffmpeg | `_腳本\剪接.py` |
| 送件 | 佇列帳本：`add` 排進來 → `wait` 送出，送出前查 `已核可/` | `_腳本\佇列.py` |

- 專案開工時，把 skill 的 `scripts\` 整個複製到專案的 `_腳本\`（含 `設定.json` 和 `設定.local.json`），送件腳本 `import comfy`。ComfyUI 只讀它自己 `input\` 裡的檔，用 `comfy.stage_input` 複製過去。
- Python、ffmpeg、模型檔名都在設定裡：`設定.json` 是 skill 附的預設，這台機器的值寫在 `設定.local.json`。開工先跑 `開工檢查.py`。
- 片長只能是 17k+5 幀（124、141、158、175、192、209、226、243、260、277、294 …）；最長是設定的 `max_frames`。
- 檔位（`comfy.PROFILES`）。同一個 seed 換檔位，畫面會不一樣。
  - 正式 `formal`：768×1344、PDD 8 步加速。出片用。PDD 只能 4／6／8 步，其他取樣器或排程會出雜訊。
  - 草稿 `draft`：416×736、PDD 8 步。只用來篩動作和構圖，不判臉；景別在正式檔位可能差一級。
  - 備用 `base20`：768×1344、基礎模型 20 步。只在 PDD 不能用時用；已知會在片中硬切或淡入白底角色卡，每一條都要跑 `cut`。

**算圖時間**（RTX 3090 實測中位數，換機器要重量）

| 項目 | 時間 |
|---|---|
| 角色板、場景卡、分鏡圖 | 每張約 1–1.5 分鐘；多張參考圖合成約 4 分鐘 |
| 片段正式（PDD 8 步） | 124 幀約 6 分鐘、158 幀約 8 分鐘、192 幀約 11 分鐘、243 幀約 17 分鐘、277 幀約 19 分鐘 |
| 片段草稿 | 124 幀約 1 分鐘；192 幀、掛 4 張圖和 2 個音色檔約 3.5 分鐘 |
| 片段備用（20 步） | 124 幀約 15 分鐘、192 幀約 26 分鐘、277 幀約 44 分鐘 |
| 音色檔、旁白每條 | 約 2.5 分鐘 |
| 配樂每條 | 10–25 秒 |

## 3. 驗片

**先量再看**（`_腳本\驗片量測.py`，只讀素材、不改素材）。每一條片段都有驗片包：佇列在 H3 片段完成時自動跑；沒跑成、或要補前後鏡的接點試看片，手動跑 `pack 片段 --first 首幀 --prev 前一鏡 --next 後一鏡`。

| 量什麼 | 指令 | 抓什麼 |
|---|---|---|
| 第 0 幀和首幀 | `frame0 片段 首幀 [尾幀]` | 首幀沒接上、開場多出東西；平均差 50 以上打開並排圖查首幀是不是被蓋掉 |
| 片中切鏡 | `cut 片段` | 片中硬切到別的畫面、淡入白底角色卡 |
| 鏡頭位移 | `drift 片段`（草稿加 `--thr 11`） | 鏡頭自己動；近景裡臉的大動作會誤判，改用 `--roi` 框一塊背景 |
| 重複幀 | `dup 片段` | 動作中卡頓 |
| 台詞時間軸 | `speech 片段` | 每句的起訖、句間停頓、說完到片尾還剩多久 |
| 分區動量 | `motion 片段`（`--grid 3x1`） | 誰在什麼時候動：反應太早或太晚 |
| 縮圖、事件條、放大 | `sheet`；`strip 片段 秒數`；`zoom 片段 x,y,寬,高 起秒 迄秒` | 整條看一遍；某個瞬間前後每一格；表情、嘴、眼睛 |
| 接點試看片 | `join 前一鏡 本鏡 後一鏡` | 連戲和情緒接不接得上 |
| 聲畫長度 | `av 片段` | 差超過一格，剪接後嘴型對不上 |
| 響度 | `loud 檔案` | 片段之間忽大忽小 |
| 尾端 | `tail 檔案 --want 秒` | 配樂、旁白提早結束 |

眨眼次數量不準，交給人看；眨太多或不眨就換 seed，不改提示詞。

**判片必檢**（每一條都打勾；有一項不對就是失敗，不寫「大致對」）
1. 人數；每件道具的數量和外觀前後一致；穿戴態。
2. 頭和臉在畫面裡（特寫照卡上寫的切法）；臉像角色板（正式檔位）；景別照分鏡卡，0–5 秒不漂。
3. 第 0 幀接得上首幀，起手接得上上一鏡。
4. 只有一個主要變化；事件發生在動作卡寫的時間（容許 ±1 秒）。
5. 鏡頭沒有自己動；沒有慢動作感；動作中不卡。
6. 台詞：只有說話人的嘴在動、說完閉上、沒有多出的人聲；字對不對由使用者聽。心聲鏡整段嘴不動。
7. 沒有片中切鏡或漏出參考圖。
8. 1 倍速完整看一遍：抽幀證明不了動作自然。

**判定**：通過／失敗／未核驗。缺證據的項目寫「未核驗」，不算通過。結果回填 `2-鏡頭表.csv` 的「狀態」「重做次數」。

**交件**：整批跑完，把驗片包排成縮圖表，連同每條的八項勾選結果一次交；cut 標「要看」的先自己看、把判定寫進 `4-影片\片段名_驗片.md`。使用者只回要重做的鏡；沒回視為過，過的片段連同它的 `驗片/片名/` 子資料夾移進 `已核可/4-生成/`（相對位置不變，`剪接.py` 才找得到驗片包）。

## 4. 失敗怎麼處理

| 類型 | 怎麼判斷 | 下一步 |
|---|---|---|
| 寫法錯 | 提示詞寫的和卡上不一樣，或句子本身不成立 | 只改那幾句，重新 lint |
| 抽卡運氣 | 寫法對，同樣寫法別的 seed 做得到 | 換 seed |
| 能力不及 | 寫法對、換 seed 也不行 | 回第 3 站改分鏡（拆鏡、換機位、換模式） |

- 還有兩條路，列進給使用者的選項：剪接補（換取段、換切點、加速）；刪鏡或合併進鄰鏡（動到核可事件是劇情改動）。
- 回報一律三段：哪一鏡、發生什麼事（一句白話）、兩個解法選項。
- 重做只改被點名的那一句，seed 不動；重做前先貼舊句→新句的對照。同一鏡同一問題最多兩輪，超過就回第 3 站；使用者給新方向算新問題；使用者明確說再試，可以超過，工單記一筆。
- 開口太晚、停頓太長、片段太長：剪接處理，不重新生成；動作卡寫明的停留秒數不剪。剪接加速救不了慢動作的物理。

## 5. 常見失敗

| 現象 | 原因 | 修正 |
|---|---|---|
| 像慢動作 | 一個動作寫成好幾句中間狀態；尾幀釘在最後一格；片長比事件長很多 | 動作一句、反應一句、停住句；不釘尾幀；用最短片長、剪接取段 |
| 撞了才灑、後果延遲 | 後果寫在下一句 | 原因和後果寫同一句（in that same instant） |
| 鏡頭自己動 | 沒寫固定鏡；動作做完的秒數沒人用 | 固定鏡句；停住句；站位句照這一鏡的機位重寫 |
| 開場就多一隻手、多一個東西 | 首幀上歸屬不明的手或物件 | 每人每隻手寫狀態；首幀先修乾淨；起手狀態寫得和首幀一模一樣 |
| 開場凍住、動作沒發生 | 首幀是動作進行中的畫面 | 首幀用動作開始前的那一刻（第 0 幀） |
| 道具變多、被重畫 | 手逐件操作道具 | 一個動作一次完成；只看不碰的道具全程不碰 |
| 多出台詞、台詞被改 | 中文寫在 `<d>` 外；同一句寫兩次 | `<d>` 外全英文；每句只寫一次 |
| 兩個人一起動嘴、說完嘴還在動 | 沒標 `(Sx)`；沒寫閉嘴句、聽的人嘴閉 | 補上 |
| 心聲對到嘴上 | 說話人就在畫面裡，旁白句擋不住 | 片段無人聲，心聲後製 |
| 無台詞的鏡出現人聲或配樂 | 聲音欄沒限定 | 只寫環境聲和動作聲，加 `These are the only sounds in the video.`；配樂 `N/A` |
| 語速太慢 | 提示詞寫 fast 沒用 | 剪接整條加速，先做 1.15、1.25 倍給使用者挑 |
| 動作中卡頓 | H3 在大動作段重複幀 | `dup` 量；換 seed，還是卡就回分鏡把動作縮短 |
| 畫外的人被拉進畫面 | 視線目標寫了畫外人物的標籤 | 視線寫畫面方向（off-screen to the right） |
| 臉、服裝跑掉 | 沒掛角色裁圖；外觀錨點太籠統；草稿檔位 | 掛裁圖、寫 4–6 個看得見的錨點；判臉看正式檔位 |
| 片中硬切、淡入白底角色卡 | 基礎模型 20 步會這樣 | 用正式檔位；每條跑 `cut` |
| 說完沒停頓就動作 | 一次生成控制不住順序；寫「保持不動」反而被跳過 | 停頓寫成看得到的小動作；一定要停頓就拆 A、B 段 |
| 對白進行中運鏡不動 | 對白蓋過運鏡 | 運鏡另拆一段、那段不放台詞 |
| 整支片表情不對 | 表情只寫在動作句 | 表情寫成角色定義句的宣告，retention 再寫一次 |
| 換手、兩隻手拿同一個東西 | 沒寫是哪一隻手 | 拿道具的手寫明，另一個動作寫明用另一隻手 |
| 只改動作句，結果幾乎沒變 | 首幀釘住又用同一個 seed | 要改時間點就換 seed；要保留構圖就不換 |
| 寫近景出中景 | 提示詞寫了畫面外的東西，或 summary、[Shot 1] 沒寫景別詞 | 刪掉畫面外的內容；景別詞寫在 summary 和 [Shot 1] 第一句 |
| 寫特寫出近景 | 沒寫被切掉的部位；角色參考圖掛全身 | 寫明頭頂、脖子、領口在畫面外；改掛 `{ID}_face` |
| 景別差一級，提示詞都照寫了 | 正式檔位的 seed 差異 | 換 seed，不改提示詞 |
| 首幀被蓋掉（第 0 幀差多半在 50 以上） | 首幀的景別或內容和提示詞衝突 | 提示詞改成和首幀一致，或換一張和提示詞一致的首幀 |
