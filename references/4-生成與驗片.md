# 4 生成與驗片（第 4 站）

## 1. 每一批生成前

1. 出片授權卡已核准：哪幾鏡、模式、檔位、條數、seed、預估時間。卡上沒列的不生成。
2. 使用者要看進度的話，在瀏覽器開一個 ComfyUI 分頁（設定的 `comfy_url`）；Windows＋Chrome 可以用 `comfy.open_chrome_once()`，開過就不再重開。
3. 每支提示詞 lint 過（❌ 不送）；每張節點圖 `comfy.check_graph` 過（佇列送件時會自動檢查）。
4. 換模型家族前清顯存（`comfy.free()`，佇列空的時候）。順序：Qwen → H3 → ACE-Step。
5. 送件走佇列帳本 `_腳本\佇列.py`：送件腳本用 `佇列.add(編號, 節點圖, [專案裡的輸出路徑], meta=…)` 一次排好，再在背景跑 `python _腳本/佇列.py wait`。完成的輸出自動複製回專案（片段到 `4-影片\`、圖到 `資產\`），每一條記進 `_腳本\生成紀錄.jsonl`。隨時用 `python _腳本/佇列.py` 看狀態；程式中斷了重跑 `wait` 就接著做。只送一條、要當場等結果時才用 `comfy.run`；H3 影片（`h3_ref`、`h3_i2v`）一律走佇列，`comfy.run` 和直接送件會被擋下。
6. 接力（下一條的首幀＝上一條的某一格）：`佇列.add(…, after=(前一條, -1, LoadImage 節點))`。前一條完成後先跑 `cut`，疑似片中切鏡或漏出參考圖就停在「等你看」，不會把壞掉的結尾接下去；人看過沒問題才用 `release` 放行。取消用 `cancel`。

**H3 影片的送件前檢查**（關卡、例外、不擋哪些工作，見 `2-分鏡.md` §12）。佇列對每一條 H3 影片生成（`h3_ref`、`h3_i2v`，任何檔位）自動檢查兩次：`佇列.add` 排進來時（沒過就丟 `comfy.GateBlocked`，不進帳本），和 `wait` 真的送到 ComfyUI 前（排進來之後關卡失效也擋得下）。H3 影片排進來先記「待送出」，由 `wait` 送出；被擋下的記「關卡擋下」，不會再送，問題解決後用新的編號重排。送件的 meta 要有「鏡」「提示詞」（編譯好的提示詞檔），拆段的鏡加「段」（A／B），用例外加「例外」（例：EXC-001）。缺一條就不送：
1. 關卡：`量產關卡.json` 是 `LOCKED`，三個指紋都對得上現在的來源；或 meta 的例外涵蓋這一鏡、這個檔位，還有剩下的條數。
2. 提示詞：meta 指的檔在，和節點圖裡的一字不差，lint 沒有 ❌（設定的外部 lint 存在就用它，命令列同 `3-提示詞.md` §5；不在就用內附的）。
3. 要掛的圖和聲音都在 ComfyUI input。
4. 參考圖照分鏡卡「素材」的資產 ID（`2-分鏡.md` §4）：都要掛、不掛別的、照順序；掛的每一張比檔案內容對到資產表核可的檔。釘幀用的首幀、尾幀、片中引導是執行中的檔，另算、不比。少掛 `ASSET_REQUIRED_MISSING`、掛了這一鏡沒有的核可資產 `ASSET_WRONG_ID`、掛了資產表沒有、沒核可或已撤回核可的 `ASSET_UNAPPROVED`、順序不對 `ASSET_ORDER_MISMATCH`（<Picture N> 會對錯）都擋。
5. 音色照音色資產表的「使用鏡頭」（`2-分鏡.md` §9）：列到這一鏡、沒加註的核可音色都要掛，加註心聲、旁白的不掛；掛的每一份比檔案內容；順序照素材的 Voice ID（<Audio N>）。少掛 `VOICE_REQUIRED_MISSING`、掛錯 `VOICE_WRONG_ID`、沒核可 `VOICE_UNAPPROVED`、順序不對 `VOICE_ORDER_MISMATCH` 都擋。
6. 首幀照鎖定的計畫：要首幀的鏡（首幀策略不是「無」，或 B 段）節點圖要釘首幀（`FIRST_FRAME_MISSING`），「無」不釘（`FIRST_FRAME_UNEXPECTED`）。接力、借格和 B 段一定要用佇列的 `after`（沒給 `RELAY_REQUIRED`）；after 的前一條要是計畫寫的那一鏡（段）、取的那一格，要換圖的節點要是釘首幀的節點，計畫不接力卻給了 after 也不行（`RELAY_SOURCE_MISMATCH`）；前一條完成、檢查過（或人 release）取到那一格才送（`RELAY_UNRESOLVED`，上面第 6 條），送出前比釘的圖就是取到的那一格；合成的鏡釘的圖要和分鏡參考圖表的「首幀檔」同內容（`FIRST_FRAME_MISMATCH`）。
7. 模式、幀數、拆段和鎖定的分鏡卡「生成」那一行一樣。例外的測試不比計畫，但給了 after 時，換圖節點和送出前那一格照樣核對。

`wait` 送出前那一次全過，檢查程式才發一張一次性的通行證（綁這個專案、這一條、這一張節點圖），`comfy._post` 只認它、用一次就作廢：檢查結果的 dict 本身、別張圖或別條的通行證、用過的通行證都送不出去（`NO_PERMIT`），所以 `comfy.run` 和直接送件擋得住 H3 影片。

狀態、檔名、重做次數、seed 照常更新，不影響鎖；生成中要改鎖定的內容，照 `2-分鏡.md` §12 的「失效」。

## 2. 本機環境

| 用途 | 模型 | 節點圖（`_腳本\comfy.py`） |
|---|---|---|
| 角色卡、場景卡 | Qwen-Image 2.1（文字生圖，cfg 1：負面欄不起作用） | `qwen_t2i` |
| 首幀、尾幀、改圖 | Qwen-Image 2.1 編輯模式，卡片當參考圖（`<image1>`…，最多 10 張） | `qwen_edit`（`size=(768,1344)`） |
| 分鏡參考圖（G5B） | 既有核可圖、裁切，或 Qwen-Image 2.1 編輯模式合成（`2-分鏡.md` §10）；不送 H3 | `qwen_edit` |
| 片段 | H3 ref2va 權重、`MiniMaxH3ReferenceToVideo`，檔位見下；首幀接第一張參考圖並用 `guide0=True` 釘在第 0 幀，尾幀用 `end_frame` | `h3_ref`（`**PROFILES[檔位]`） |
| 音色檔 | H3 fl2va，416×736，只解音訊 | `h3_voice` |
| 旁白、心聲 | H3 參考模式，416×736，只解音訊，掛音色檔 | `h3_vo` |
| 配樂 | ACE-Step 1.5 turbo | `ace` |
| 剪接、混音 | ffmpeg | `_腳本\剪接.py` |
| Animatic（G5C） | ffmpeg：靜態分鏡參考圖照秒數硬切、疊預覽語音、QC 疊字（`2-分鏡.md` §11） | `_腳本\剪接.py`（`image`＋`seconds`、`overlays`、`qc_overlay`、`--dry-run`） |
| 量產關卡（G5D） | 鎖定前置、Final Shot Lock、三個指紋、例外（`2-分鏡.md` §12） | `_腳本\檢查量產Gate.py`（`ready`／`lock`／`check`／`fingerprint`／`invalidate`／`exception`） |
| H3 送件 | 佇列帳本：`add` 排進來（H3 影片先「待送出」）→ `wait` 送出前檢查、發一次性通行證才送（§1） | `_腳本\佇列.py` |

- 專案開工時，把 skill 的 `scripts\` 整個複製到專案的 `_腳本\`（含 `設定.json` 和 `設定.local.json`），每一站的送件腳本 `import comfy`。ComfyUI 只讀它自己 `input\` 裡的檔，用 `comfy.stage_input` 複製過去。
- Python、ffmpeg、模型檔名都在設定裡：`設定.json` 是 skill 附的預設，這台機器的值寫在 `設定.local.json`。開工先跑 `開工檢查.py`。
- 片長只能是 17k+5 幀（規則核心 §2.2）；正式解析度最長是設定的 `max_frames`，再長會爆顯存，換顯卡要重量。
- 檔位（`comfy.PROFILES`）。同一個 seed 換檔位，畫面會不一樣。
  - 正式 `formal`：768×1344、PDD 8 步加速。出片用。配方：`MiniMaxH3SigmaShift`（12／3）→ `MiniMaxH3PDDAccApply` → euler、用加速節點給的 sigmas、`BasicGuider`（等於 CFG 1）。PDD 只能 4／6／8 步，不能拿來跑 20 步，其他取樣器或排程會出雜訊。
  - 草稿 `draft`：416×736、PDD 8 步，參考圖縮放和正式一樣用 match。只用來篩動作和構圖，不判臉；景別在正式檔位可能差一級，定案看正式。
  - 備用 `base20`：768×1344、基礎模型 20 步（res_multistep、beta）。只在 PDD 不能用時用。已知會在片中硬切或淡入白底角色卡，掛不掛音色檔都會；每一條都要跑 `cut`。

## 3. 驗片

**先量再看**（`_腳本\驗片量測.py`，量測只讀素材、不改素材）

每一條片段先跑驗片包：`pack 片段 --first 首幀 [--end 尾幀] [--prev 前一鏡] [--next 後一鏡]`。它一次跑完下表的量測，在 `4-影片\驗片\片段名\` 產出縮圖、第 0 幀比對、接點試看片，和一份 `驗片包.md`（量測數字＋判片必檢草稿，全部先寫「未核驗」）。人看過以後，判定寫進 `4-影片\片段名_驗片.md`。

| 量什麼 | 指令 | 抓什麼 |
|---|---|---|
| 第 0 幀和首幀 | `frame0 片段 首幀 [尾幀]` | 首幀沒接上、開場多出東西；平均差 50 以上要打開並排圖查核首幀是不是被蓋掉，是的話先查提示詞的景別和內容是不是和首幀衝突 |
| 片中切鏡 | `cut 片段` | 片中硬切到別的畫面、淡入白底角色卡（參考圖漏進影片） |
| 鏡頭位移 | `drift 片段`（草稿檔位加 `--thr 11`） | 鏡頭自己動。近景、特寫裡臉的大動作會讓自動模式誤判，改用 `--roi` 框一塊背景；量測超標但人工判讀可接受時，兩個結果都記 |
| 重複幀 | `dup 片段` | 動作中卡頓 |
| 台詞時間軸 | `speech 片段` | 每句的起訖、句間停頓、說完到片尾還剩多久 |
| 分區動量 | `motion 片段`（`--grid 3x1`＝左中右） | 誰在什麼時候動：反應太早或太晚、說完有沒有停頓才動 |
| 縮圖、事件條、放大 | `sheet 片段`；`strip 片段 秒數`；`zoom 片段 x,y,寬,高 起秒 迄秒` | 整條看一遍；某個瞬間前後每一格；表情、嘴、眼睛 |
| 接點試看片 | `join 前一鏡 本鏡 後一鏡` | 前一鏡結尾＋本鏡＋後一鏡開頭接起來看，連戲和情緒接不接得上 |
| 聲畫長度 | `av 片段` | 畫面和聲音差超過一格，剪接後嘴型會對不上 |
| 響度 | `loud 檔案` | 片段之間忽大忽小 |
| 尾端 | `tail 檔案 --want 秒` | 配樂、旁白提早結束 |

眨眼次數量不準，交給人看；眨太多或不眨就換 seed，不改提示詞。

**判片必檢**（每一條都打勾；有一項不對就是失敗，不寫「大致對」）
1. 人數；每件道具的數量和外觀前後一致；穿戴態。
2. 頭和臉在畫面裡（特寫照卡上寫的切法）；臉像角色卡（正式檔位）；景別照分鏡卡，0–5 秒不漂。
3. 第 0 幀接得上首幀，起手接得上上一鏡。
4. 只有一個主要變化；事件發生在動作卡寫的時間（容許 ±1 秒）。
5. 鏡頭沒有自己動；沒有慢動作感；動作中不卡。
6. 台詞：只有說話人的嘴在動、說完閉上、沒有多出的人聲；字對不對由使用者聽（本機沒有語音辨識）。心聲鏡整段嘴不動。
7. 沒有片中切鏡或漏出參考圖。
8. 1 倍速完整看一遍：抽幀證明不了動作自然。

**判定**：通過／失敗／未核驗。缺證據的項目寫「未核驗」，不算通過。結果回填 `2-鏡頭表.csv` 的「狀態」「重做次數」。

**使用者審片**：把待審的檔名列給使用者，附上驗片包的重點。使用者逐條回「檔名＋過」就是那一條核可，回「檔名＋改法」就是那一條的重做授權（送出前說一聲預估時間）。沒指明哪一條的「好」「繼續」不算，回問是哪幾條。每回一條就更新鏡頭表的「狀態」。

## 4. 失敗怎麼處理

先分類，再決定下一步：

| 類型 | 怎麼判斷 | 下一步 |
|---|---|---|
| 寫法錯 | 提示詞寫的和卡上不一樣，或句子本身不成立 | 只改那幾句，重新 lint |
| 抽卡運氣 | 寫法對，同樣寫法別的 seed 做得到 | 換 seed |
| 能力不及 | 寫法對、換 seed 也不行 | 回第 2 站改分鏡（拆鏡、換機位、換模式） |

- 還有兩條路，列進給使用者的選項：剪接補（換取段、換切點、加速）；刪鏡或合併進鄰鏡。對應核可事件的鏡刪掉是劇情改動；2A 自己加的鏡也一樣列給使用者決定（`2A-分鏡敘事.md` §8、§15）。
- 回報給使用者一律用三段格式：哪一鏡、發生什麼事（一句白話）、兩個解法選項。
- 使用者的意見逐條記：時間點／現在的問題／要改成什麼／原因。
- 重做照字面：使用者說換 seed 就只換 seed，說改鏡位就只改鏡位；覺得還有別的該改，先問，不順手改。
- 提出重做前先寫：保留什麼、改什麼（只改造成問題的那幾句或一個設定）、為什麼、預期看到什麼。判定標準在重做前寫死。
- 開口太晚、停頓太長、片段太長：剪接處理，不重新生成；動作卡 K 寫明的停留、延宕秒數不剪。
- 重做上限，每鏡記在鏡頭表「重做次數」：
  - 技術失敗（片子沒做到分鏡卡寫的）：同一個問題第一次加兩次重做；重生首幀也算；換模式、拆段、換個說法描述同一個問題都不重新計算。到上限就停，回第 2 站或第 1 站。
  - 使用者給新方向（改表演、時間點、鏡位、情緒）：算新問題，重新計算。
  - 使用者明確說要繼續試：可以超過上限，在工單記一筆。
- 剪接加速救不了動作的物理（像慢動作的鏡要重生或改分鏡，不靠加速）。

## 5. 常見失敗

| 現象 | 原因 | 修正 |
|---|---|---|
| 像慢動作 | 一個動作寫成好幾句中間狀態；尾幀釘在最後一格；片長比事件長很多 | 動作一句、反應一句、停住句；不釘尾幀；用最短片長、剪接取段 |
| 撞了才灑、後果延遲 | 後果寫在下一句 | 原因和後果寫同一句（in that same instant） |
| 撞得像約好 | 兩人互相看得見；首幀距離太遠 | 兩人各看各的；首幀距離 ÷ 真實速度 ≤ 1 秒 |
| 鏡頭自己動 | 沒寫固定鏡；動作做完的秒數沒人用；繼承的站位句要鏡頭換角度才成立 | 固定鏡句；停住句；站位句照這一鏡的機位重寫 |
| 開場就多一隻手、多一個東西 | 首幀上歸屬不明的手或物件；參考模式的首幀沒被釘住 | 每人每隻手寫狀態；首幀先修乾淨；起手狀態寫得和首幀一模一樣 |
| 開場凍住、動作沒發生 | 首幀是動作進行中的畫面 | 首幀用動作開始前的那一刻 |
| 手停在半空 | 寫了起手姿勢、接觸過程或停頓 | 一句動作一句反應，拿掉停頓的字 |
| 道具變多、被重畫 | 手逐件操作道具 | 一個動作一次完成；只看不碰的道具全程不碰 |
| 多出台詞、台詞被改 | 中文寫在 `<d>` 外；同一句寫兩次 | `<d>` 外全英文；每句只寫一次 |
| 兩個人一起動嘴、說完嘴還在動 | 沒標 `(Sx)`；沒寫閉嘴句、聽的人嘴閉 | 補上 |
| 心聲對到嘴上 | 說話人就在畫面裡，旁白句擋不住 | 片段無人聲，心聲後製 |
| 無台詞的鏡出現人聲或配樂 | 聲音欄沒限定 | 聲音欄只寫環境聲和動作聲，加 `These are the only sounds in the video.`；配樂 `N/A` |
| 語速太慢 | 提示詞寫 fast 沒用 | 剪接整條加速，先做 1.15、1.25 倍給使用者挑 |
| 動作中卡頓 | H3 在大動作段重複幀（實測一條有 7–9 次） | `dup` 量；換 seed，還是卡就回分鏡把動作縮短 |
